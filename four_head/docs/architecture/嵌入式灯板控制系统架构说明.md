# 嵌入式灯板/电磁炉控制系统架构说明

---

## 一、设计目标

将一个传统的灯板控制程序重构为**低业务耦合、多模块**的架构。各模块之间采用**消息+回调**机制通信，尽可能采用异步方式，仅保留蜂鸣器等极少数直接回调通道。

---

## 二、核心设计思想

### 2.1 时间触发架构

系统以**1毫秒定时中断**为唯一调度节拍。所有任务执行时机确定，不存在抢占问题。

text

1ms中断 → 蜂鸣器状态机 + 消息调度器
主循环   → 各模块后台任务

### 2.2 消息机制

业务模块之间不直接互相调用，通过消息传递信息。

- **消息槽**：使用环形队列存储待处理消息，每1毫秒消费一条。
    
- **回调注册**：各模块在初始化时向调度器注册感兴趣的消息ID及对应回调函数。
    
- **数据指针**：通讯返回的共享数据（温度、状态等）存储在调度器内部，通过回调传指针给各模块，无需拷贝。
    

### 2.3 通道分级

|通道类型|用途|延迟|实现方式|
|---|---|---|---|
|**消息+指针**|所有业务事件和数据|≤1ms|`Msg_Post` → 调度器 → 回调|
|**直接回调**|蜂鸣器|0延迟|`BUZZER_Beep()` 直接调用|

## 四、消息调度器详解

### 4.1 数据结构

c

// 消息槽（环形队列）
static Msg_t msgSlot[MSG_SLOT_DEPTH];
static uint8_t slotHead, slotTail, slotCount;
// 回调注册表
static HandlerEntry_t handlers[MAX_HANDLERS];
static uint8_t handlerCount;
// 通讯数据内部存储（只此一份）
static CommData_t commData;

### 4.2 注册机制

各模块在初始化时通过 `MsgScheduler_Register` 注册回调：

c

void UI_Init(void) {
    MsgScheduler_Register(MSG_KEY_EVENT,        UI_OnKeyEvent);
    MsgScheduler_Register(MSG_DISPLAY_REFRESH,   UI_OnDisplayRefresh);
    MsgScheduler_Register(MSG_COMM_DATA_UPDATE,  UI_OnCommDataUpdate);
    MsgScheduler_Register(MSG_SYSTEM_ERROR,      UI_OnSystemError);
}

同一个消息ID可注册多个回调（多个模块关心同一事件），调度器会依次调用。

### 4.3 消息发送

任何模块通过 `Msg_Post` 发送消息：

c

Msg_Post(MSG_POWER_CTRL, 2000);     // 下发2000W功率
Msg_Post(MSG_COOKING_CTRL, 0x01);   // 开始烹饪
Msg_Post(MSG_FAN_CTRL, 3);          // 风机3档

消息写入环形队列槽位，等待1ms调度器取出处理。

### 4.4 1毫秒调度流程

text

MsgScheduler_Run1ms()
  │
  ├─ 检查消息槽是否为空
  │    └─ 空 → 直接返回
  │
  ├─ 取出消息（slotCount-1，head指针移动）
  │
  ├─ 遍历回调注册表
  │    └─ 匹配消息ID的回调全部调用
  │         handler(msg, NULL)  // 普通消息不传额外数据
  │
  └─ 结束（消息已消费，槽位已释放）

### 4.5 通讯数据更新流程

这是唯一不走消息槽的特殊通道：

text

I²C/串口接收中断
  │
  └─→ PROTO_OnByteReceived(byte)
       │
       ├─ 收满一帧，校验通过
       │
       └─→ MsgScheduler_UpdateCommData(&parsedData)
            │
            ├─ 更新内部 commData
            │
            └─ 遍历所有注册了 MSG_COMM_DATA_UPDATE 的模块
                 └─ handler(NULL, &commData)  // 直接传数据指针

各模块在回调里直接通过指针读取数据，无需拷贝，读完后指针失效。

## 五、模块职责

### 5.1 人机交互模块 (UI)

|职责|说明|
|---|---|
|接收按键|通过 MSG_KEY_EVENT 回调处理|
|分发命令|根据按键值发送 MSG_COOKING_CTRL、MSG_FAN_CTRL 等|
|刷新显示|接收 MSG_DISPLAY_REFRESH 更新屏幕|
|状态显示|接收 MSG_COMM_DATA_UPDATE 显示温度、故障等|
|蜂鸣器|直接调用 BUZZER_Beep() 提供按键音和报警音|

### 5.2 烹饪逻辑模块 (Cook)

|职责|说明|
|---|---|
|菜谱管理|内部维护烹饪步骤表（时间、功率、风机档位）|
|状态机|通过 MSG_TIMER_100MS 驱动计时和阶段切换|
|功率控制|发送 MSG_POWER_CTRL 下发目标功率|
|风机控制|发送 MSG_FAN_CTRL 控制散热|
|异常处理|接收 MSG_COMM_DATA_UPDATE 检测电磁炉故障|

### 5.3 协议模块 (Proto)

|职责|说明|
|---|---|
|打包|接收 MSG_POWER_CTRL，打包成通讯帧通过 I²C 发出|
|解包|接收字节流，解析帧结构，校验|
|数据更新|解包成功后调用 MsgScheduler_UpdateCommData|
|超时检测|内部维护超时计时，超时后更新 commData.commStatus|

### 5.4 执行器模块 (Actuator)

|职责|说明|
|---|---|
|风机|接收 MSG_FAN_CTRL，操作硬件IO|
|加热使能|接收 MSG_POWER_CTRL，控制继电器|

### 5.5 蜂鸣器模块 (Buzzer)

|职责|说明|
|---|---|
|直接回调|BUZZER_Beep(times, interval) 任何模块直接调用|
|状态机|BUZZER_Tick1ms() 在1ms中断里维护鸣叫时序|

## 六、消息定义

### 6.1 消息ID

|消息ID|含义|param|
|---|---|---|
|MSG_KEY_EVENT|按键事件|键值|
|MSG_COOKING_CTRL|烹饪控制命令|低8位命令，高8位参数|
|MSG_POWER_CTRL|功率/加热控制|功率值（0=关）|
|MSG_FAN_CTRL|风机控制|档位（0-3）|
|MSG_DISPLAY_REFRESH|显示刷新|显示内容编码|
|MSG_TIMER_100MS|100ms节拍|无|
|MSG_COMM_DATA_UPDATE|通讯数据更新|无（通过dataPtr传数据）|
|MSG_SYSTEM_ERROR|系统错误|错误码|

### 6.2 通讯数据结构

c

typedef struct {
    uint16_t igbtTemp;      // IGBT温度
    uint16_t surfaceTemp;   // 表面温度
    uint16_t coilCurrent;   // 线圈电流
    uint16_t systemState;   // 电磁炉状态字
    uint8_t  faultCode;     // 故障码（0=正常）
    uint8_t  commStatus;    // 0=正常, 1=超时, 2=校验错
} CommData_t;

## 七、典型消息流

### 7.1 用户按开始键

text

按键中断
  → Msg_Post(MSG_KEY_EVENT, KEY_START)
     ↓ (等待1ms)
1ms调度器
  → UI_OnKeyEvent()
     → BUZZER_Beep(1, 50)            // 确认音，直接回调
     → Msg_Post(MSG_COOKING_CTRL, 0x01)
        ↓ (等待1ms)
1ms调度器
  → COOK_OnCookingCtrl()
     → Msg_Post(MSG_POWER_CTRL, 2000)
     → Msg_Post(MSG_FAN_CTRL, 3)
     → Msg_Post(MSG_DISPLAY_REFRESH, 倒计时)
        ↓ (等待1ms)
1ms调度器
  → ACT_OnPowerCtrl()     // 开加热
  → PROTO_OnSendPower()   // 下发功率到电磁炉
  → ACT_OnFanCtrl()       // 开风机
  → UI_OnDisplayRefresh() // 更新屏幕

### 7.2 电磁炉主动上报状态

text

I²C接收中断
  → PROTO_OnByteReceived(byte)
     → 收满一帧，校验通过
     → MsgScheduler_UpdateCommData(&parsedData)
        → UI_OnCommDataUpdate(&commData)    // 更新温度显示
        → COOK_OnCommDataUpdate(&commData)  // 检测故障

### 7.3 烹饪阶段切换

text

100ms定时 → 累计10次=1秒
  → COOK_OnTimer()
     → 当前步骤时间到
     → Msg_Post(MSG_POWER_CTRL, 新功率)
     → Msg_Post(MSG_FAN_CTRL, 新档位)
     → Msg_Post(MSG_DISPLAY_REFRESH, 新倒计时)
     → BUZZER_Beep(1, 80)   // 阶段切换提示音

## 八、设计原则总结

1. **默认异步**：所有模块间通信走消息槽，不直接调用。
    
2. **数据集中**：通讯数据统一存储在调度器内部，通过指针共享，模块只读不写。
    
3. **极简直接通道**：仅蜂鸣器保留直接回调，保证提示音零延迟。
    
4. **时间确定性**：1ms节拍驱动，无抢占，任务执行顺序可预测。
    
5. **无全局变量**：所有模块不暴露全局变量，数据流向清晰可控。
    
6. **通讯封装**：协议模块完全隐藏在调度器之后，其他模块感知不到 I²C 的存在。
