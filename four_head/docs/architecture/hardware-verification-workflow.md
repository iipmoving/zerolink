# 硬件控件验证工作流 (Hardware Verification Workflow)

> 目标: JSON→C 转换后，通过测试模式逐项确认物理硬件与 JSON 配置的对应关系。
> 覆盖: 按键映射 / LED 映射 / 数码管段位 / COM 口 / 触摸通道。

---

## 一、核心原则

1. **JSON 是唯一真相源** — 所有硬件映射关系最终写入 JSON→C 生成器
2. **测试模式不依赖业务逻辑** — `HMI_DEBUG_KEYS` 宏完全旁路 HMI 状态机
3. **每次物理变更后重跑验证** — PCB 改版、触摸通道调整、LED 重分配后必须走完整流程

---

## 二、测试模式总览

| 模式 | 进入方式 | 界面特征 | 用途 |
|------|---------|---------|------|
| 按键调试 | 编译 `HMI_DEBUG_KEYS` 后上电 | 上排=键码hex, 下排=按键状态 | 验证每个触摸焊盘的键码和事件 |
| LED 测试 | 按键调试模式下长按开关 | 上排=L+编号, 下排=LED名称, 仅此LED亮 | 逐一确认每个LED物理位置和编号 |
| 段码测试 | (待实现) | 逐段/逐COM点亮 | 确认SEG→COM→显示区映射 |
| COM 测试 | (待实现) | 逐COM扫描 | 确认COM口顺序和物理位置 |

## 三、按键调试模式操作

### 编译
```c
// Claude/app/app_hmi.c 第18行, 取消注释:
#define HMI_DEBUG_KEYS
```

### 界面说明
```
┌──────────────┬──────────────┐
│    (空格)     │ 键码 (hex)    │  ← Upper Panel (Z1+Z2)
│              │  例: 0B=POT1  │
├──────────────┼──────────────┤
│    (空格)     │ 状态 (hex)    │  ← Lower Panel (Z3+Z4)
│              │ 01=PRESS      │
│              │ 02=LONG       │
│              │ 10=TAP        │
└──────────────┴──────────────┘
```

### 操作步骤
1. 烧录后上电，显示全灭
2. **依次触摸每个焊盘**，记录键码和按键状态
3. 对比 PCB 丝印与记录的键码，确认 `drv_key.c` 中 `s_key_map[]` 映射正确
4. 按功率键 0-9，确认 `KEY_POWER_0` ~ `KEY_POWER_9` 键码正确
5. 检查组合键（相邻功率焊盘同时触摸）

### 记录模板
```
| PCB丝印 | 触摸通道 | 预期KeyCode | 实际键码(hex) | 状态 |
|---------|---------|------------|-------------|------|
| POT1    | ?       | KEY_LEFT_P_SET_UP(0x0B) | 0B | ✅ |
| POT2    | ?       | KEY_LEFT_P_SET(0x09)    | 09 | ✅ |
| ...     | ...     | ...        | ...         | ...  |
```

## 四、LED 测试模式操作

### 进入/退出
- **进入**: 按键调试模式下，**长按开关** → 显示 `L 0` + `Po`，电源LED单独亮起
- **退出**: LED 测试模式下，**长按开关** → 回到按键调试模式
- **遍历**: 按 **+** 递增编号，按 **-** 递减编号（循环）

### LED 编号表 (0-17)

| 编号 | 显示名 | 物理LED | IO位 | 分类 |
|------|--------|---------|------|------|
| 0 | Po | 电源 LED | IO10.3 (LED6) | 状态LED |
| 1 | ti | 定时 LED | IO10.4 (LED2) | 状态LED |
| 2 | PA | 暂停 LED | IO10.0 (LED3) | 状态LED |
| 3 | CL | 童锁 LED | IO10.7 (LED5) | 状态LED |
| 4 | H1 | 炉头选中 Z1 | IO8.2 (LED1) | 选头LED |
| 5 | H2 | 炉头选中 Z2 | IO9.5 (LED7) | 选头LED |
| 6 | H3 | 炉头选中 Z3 | IO9.1 (LED8) | 选头LED |
| 7 | H4 | 炉头选中 Z4 | IO9.0 (LED9) | 选头LED |
| 8 | L0 | 档位 0 | IO9.4 (LED10) | 档位LED |
| 9 | L1 | 档位 1 | IO8.4 (LED11) | 档位LED |
| 10 | L2 | 档位 2 | IO8.0 (LED12) | 档位LED |
| 11 | L3 | 档位 3 | IO8.1 (LED13) | 档位LED |
| 12 | L4 | 档位 4 | IO8.5 (LED14) | 档位LED |
| 13 | L5 | 档位 5 | IO8.7 (LED15) | 档位LED |
| 14 | L6 | 档位 6 | IO8.3 (LED16) | 档位LED |
| 15 | L7 | 档位 7 | IO10.1 (LED4) | 档位LED |
| 16 | L8 | 档位 8 | (无物理LED) | 档位LED |
| 17 | L9 | 档位 9 | (无物理LED) | 档位LED |

### 操作步骤
1. 进入 LED 测试模式（长按开关）
2. 按 **+** 从 0 到 17 遍历，确认每个编号对应物理 LED 正确亮起
3. **重点检查**:
   - 状态 LED (0-3): 确认位置和亮度
   - 选头 LED (4-7): 确认 Z1-Z4 物理位置与 PCB 丝印一致
   - 档位 LED (8-17): L8/L9 应无实际 LED 亮起（确认后标记）
4. 发现错误 → 更新 `drv_display.c` 中的 IO 位宏定义
5. LED 顺序变更 → 更新 JSON → 重新生成 `hmi_data.c` → 重新编译验证

### 发现错误后的修复链路
```
LED测试发现错误 → 修改 drv_display.c 中对应 HMI_LED_* 宏
                → 修改 JSON elements.led 中对应字段
                → 重新运行 gen_hmi.js 生成 hmi_data.c
                → 重新编译 → 重新LED测试验证
```

## 五、段码/COM 测试模式（待实现）

### 设计思路
```
模式进入: LED测试中再长按某个键 → 段码测试
界面: 上排显示 "S" + SEG编号(0-7=A-H), 下排显示 "C" + COM编号(0-10)
操作: + 切换SEG, - 切换COM
效果: 仅点亮选中的 SEG×COM 交叉点
```

### 预期验收项
| 验收项 | 方法 |
|--------|------|
| SEG A-H 对应物理段 | 固定COM, 遍历SEG 0-7 |
| COM 0-10 物理顺序 | 固定SEG, 遍历COM 0-10 |
| Z1-Z4 显示区边界 | 点亮相邻2个COM, 确认显示区划分 |
| 无偷亮 (ghosting) | 单点测试: 仅1 SEG + 1 COM 亮, 其他全灭 |

## 六、标准验证流程 (每次 JSON 变更后)

```
1. 编译 DEBUG 固件 (#define HMI_DEBUG_KEYS)
2. 烧录 → 上电
3. 【按键调试】逐一触摸所有焊盘，记录键码 → 对比键码映射表
4. 【LED 测试】长按开关进入，+ 遍历 0-17 → 确认每个 LED
5. 【段码测试】(待实现) 确认 SEG/COM → 显示区映射
6. 发现差异 → 更新对应源文件 → 重新编译 → 重新验证
7. 全部通过 → 注释 #define HMI_DEBUG_KEYS → 编译正式固件
8. 正式固件功能测试
```

---

## 七、扩展到新硬件平台

当更换 PCB 或 MCU 时:

1. **触摸通道变更**: 修改 `drv_key.c` 的 `s_key_map[]` → 按键调试验证
2. **LED IO 变更**: 修改 `drv_display.c` 的 `HMI_LED_*` 宏 → LED 测试验证
3. **SEG/COM 变更**: 修改 `hal_display.c` 的引脚映射 → 段码测试验证
4. **所有变更**: 同步更新 JSON 配置 → 重新生成 → 完整流程重跑
