# 启动脚本使用说明

## 🎯 核心原理

### 相对路径的重要性

HTML文件中使用的所有资源路径都是**相对路径**：

```html
<!-- index.html 中的引用 -->
<script src="js/app.js"></script>
<script src="js/demo.js"></script>
<link rel="stylesheet" href="css/style.css">
<img src="assets/reference/panel.png">
```

这些路径相对于**当前工作目录**，而不是脚本文件的位置。

### 问题场景

如果从其他目录运行脚本：

```bash
# ❌ 错误：从D盘根目录运行
D:\> D:\Projects\emc-web\phase1-js-logic-release\自动启动.bat

# 结果：
# - 工作目录是 D:\
# - HTML尝试加载 D:\js\app.js（不存在）
# - 所有资源加载失败
```

### 解决方案

在脚本开头添加：

```batch
cd /d "%~dp0"
```

这行代码的作用：
- `%~dp0` = 脚本文件所在的驱动器和路径
- `cd /d` = 切换到该目录（包括切换驱动器）

**效果**：无论从哪里运行脚本，工作目录都会切换到脚本所在文件夹。

## 🔧 技术细节

### cd /d "%~dp0" 详解

#### 组成部分

1. **`cd`** - Change Directory（改变目录）
2. **`/d`** - 同时切换驱动器（Drive）
3. **`"%~dp0"`** - 批处理参数扩展

#### 参数扩展说明

| 符号 | 含义 | 示例 |
|------|------|------|
| `%0` | 脚本文件的完整路径 | `D:\Projects\test.bat` |
| `%~d0` | 驱动器 | `D:` |
| `%~p0` | 路径 | `\Projects\` |
| `%~dp0` | 驱动器+路径 | `D:\Projects\` |

#### 实际效果

假设脚本位于：`D:\Projects\emc-web\phase1-js-logic-release\自动启动.bat`

```batch
:: 执行前
当前目录: C:\Users\Username

:: 执行 cd /d "%~dp0"
当前目录: D:\Projects\emc-web\phase1-js-logic-release\
```

### 为什么需要 /d 参数？

```batch
:: ❌ 没有 /d：只能切换同驱动器的目录
cd C:\Windows    :: 可以
cd D:\Projects   :: 失败（不同驱动器）

:: ✅ 有 /d：可以切换任意驱动器的目录
cd /d C:\Windows    :: 可以
cd /d D:\Projects   :: 可以
```

### 常见错误

#### ❌ 错误1：手动命令行启动

```bash
# 错误做法
cd D:\
python -m http.server 8080
# 工作目录是 D:\，资源路径错误
```

#### ✅ 正确做法

```bash
# 方法1：双击脚本（推荐）
双击 自动启动.bat

# 方法2：先进入目录
cd D:\Projects\emc-web\phase1-js-logic-release
python -m http.server 8080
```

#### ❌ 错误2：移动文件后路径失效

```
原结构：
phase1-js-logic-release/
├── index.html
├── js/
└── css/

移动后：
Desktop/
├── index.html      ← 单独移动
└── phase1-js-logic-release/
    ├── js/
    └── css/

结果：index.html 找不到 js/app.js
```

#### ✅ 正确做法

```
始终复制整个文件夹，不要单独移动文件
```

## 🎓 扩展知识

### 相对路径 vs 绝对路径

#### 相对路径（本项目使用）

```html
<script src="js/app.js"></script>
```
- 优点：可移植性强，可以在任何位置运行
- 缺点：依赖正确的当前工作目录

#### 绝对路径

```html
<script src="D:/Projects/js/app.js"></script>
```
- 优点：不依赖当前目录
- 缺点：只能在特定位置运行，不可移植

### 最佳实践

Web项目应该：
1. ✅ 使用相对路径
2. ✅ 确保脚本设置正确的工作目录
3. ✅ 保持文件结构完整
4. ❌ 避免硬编码绝对路径

## 🔍 验证方法

### 检查当前工作目录

在脚本中添加调试信息：

```batch
@echo off
cd /d "%~dp0"
echo Current directory: %CD%
pause
```

### 测试相对路径

```batch
@echo off
cd /d "%~dp0"

:: 检查文件是否存在
if exist "index.html" (
    echo ✅ index.html found
) else (
    echo ❌ index.html NOT found
)

if exist "js\app.js" (
    echo ✅ js/app.js found
) else (
    echo ❌ js/app.js NOT found
)

pause
```

## 📞 故障排除

### Q: 双击脚本后提示"文件未找到"？

**A**: 
1. 确认整个文件夹已完整复制
2. 检查是否缺少js/、css/等子文件夹
3. 不要单独移动index.html文件

### Q: 浏览器打开后显示空白？

**A**:
1. 按F12打开开发者工具
2. 查看Console标签的错误信息
3. 确认是否有404错误（文件未找到）
4. 检查工作目录是否正确设置

### Q: 从快捷方式运行失败？

**A**:
1. 右键快捷方式 → 属性
2. 检查"起始位置"字段
3. 应该设置为脚本所在文件夹
4. 或者直接双击原始脚本文件
