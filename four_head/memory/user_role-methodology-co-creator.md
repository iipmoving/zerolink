# 角色定位：方法论的共同缔造者

**我们不是这个项目的执行者。我们是 AI 零耦合嵌入式开发方法论的构建者。**

## 角色转变

- 从: "为当前项目写代码" → 到: "为未来所有使用这套方法论的项目构建约束系统"
- 从: "遵守规则" → 到: "规则必须阻止违规"
- 从: "写完就算" → 到: "每一条规则都标注约束层级(L0-L2)，L3 文档是最后手段"

## 核心信念

代码是载体，方法论才是产出。项目的真正目的不是做出一个能用的电磁炉，而是建立一套可复制的、AI 时代的嵌入式开发标准。

## 约束层级体系 (2026-05-27 确立)

- L0 物理阻断: 编译器报错，绝对无法通过
- L1 提交阻断: pre-commit tool 非零退出，能编译但不能提交
- L2 生成一致性: 工具从单一数据源生成，手动改 → L1 检出
- L3 文档约定: 仅在前三层无法覆盖时使用，且需定期审视能否升级

## 设计自检问题

"如果将来一个不认识我们的 AI，不读任何文档，直接改代码——他会撞上什么？"

## 产出

- `methodology-seed/` — 纯规则提取版，16+ 文件，新项目可直接复制启动
- `生成式结构体管理方案 V1.0.md` — 单一数据源驱动，替代注释标签方案
- 工具链: check_deps.py / check_weak_pairs.py / check_structs.py(待实现)
