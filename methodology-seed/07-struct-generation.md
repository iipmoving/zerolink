# 07 — 生成式结构体管理

---

## 一、为什么用生成式而不是注释标签

**核心命题**: 跨模块结构体的一致性不能依赖操作者（人/AI）的自觉。必须做到"工具阻断 > 自觉遵守"。

| 方式 | 数据源 | 一致性保证 | 换操作者后 |
|------|--------|-----------|-----------|
| 注释标签 | 散落在各 .h 的注释 | 依赖标签被正确写入+解析 | 新 AI 可能不知标签语法 |
| **生成式** | 单一 `structs.json` | 从数据源确定性生成 | 新 AI 读到 AUTO-GENERATED 就知道路径 |

生成式的原则：**只有一个地方需要编辑，其余文件由工具生成。修改生成文件将被阻断。**

---

## 二、数据流

```
cfg/structs.json        ← 人/AI 唯一编辑点
        │
        ▼
generate_structs.py     ← 读 JSON, 生成各模块 types.h
        │
        ├──→ state_module/types.h    (AUTO-GENERATED)
        ├──→ display_module/types.h  (AUTO-GENERATED)
        ├──→ timer_module/types.h    (AUTO-GENERATED)
        └──→ ...
                │
                ▼
check_structs.py        ← 重新生成 → diff → 不一致即阻断
```

## 三、structs.json Schema

```json
{
  "version": "1.0",
  "serial": 1,
  "structs": {
    "<StructKey>": {
      "description": "...",
      "owner": "<模块名>",
      "suffix": "OUT | IN | \"\"",
      "fields": [
        {"name": "...", "type": "uint8_t", "count": 4, "note": "..."}
      ],
      "consumers": {
        "<模块名>": {
          "fields": ["field1", "field2"],
          "struct_name": "可选自定义名"
        }
      },
      "deprecated": {
        "<字段名>": {
          "replaced_by": "...",
          "deadline": "YYYY-MM-DD",
          "note": "..."
        }
      }
    }
  }
}
```

### 字段说明

| 字段 | 必须 | 说明 |
|------|------|------|
| `version` | 是 | Schema 版本，当前 `"1.0"` |
| `serial` | 是 | 单调递增。每次编辑 +1。生成文件内嵌此值用于比对 |
| `description` | 是 | 结构体用途 |
| `owner` | 是 | 拥有该结构体的模块 |
| `suffix` | 是 | `"OUT"` = 模块产出, `"IN"` = 模块接收, `""` = 私有 |
| `fields[].name` | 是 | 字段名 (snake_case) |
| `fields[].type` | 是 | C 类型: `uint8_t`, `uint16_t`, `uint32_t`, `int8_t`, `int16_t`, `int32_t`, `char` |
| `fields[].count` | 否 | 数组长度。省略 = 非数组 |
| `fields[].note` | 否 | 字段说明 |
| `consumers` | 否 | 消费此结构体的模块。{} = 仅 owner 使用 |
| `consumers.{m}.fields` | 是 | 该模块需要的字段名列表 |
| `consumers.{m}.struct_name` | 否 | 自定义结构体名，默认 `{Module}_{StructKey}_IN_t` |
| `deprecated` | 否 | 废弃字段。不应出现在任何 consumer 的 fields 中 |

## 四、生成规则

### Owner 结构体

```c
// state_module/types.h (AUTO-GENERATED)
typedef struct {
    uint8_t  head_power[4];       /* 4个炉头的功率档位 */
    uint8_t  work_mode;           /* 系统工作模式 */
    uint16_t timer_remaining;     /* 定时剩余秒数 */
    uint8_t  timer_active;        /* 定时是否激活 */
} StateGlobal_OUT_t;
```

- 包含所有字段
- 结构体名 = `{StructKey}_{suffix}_t`

### Consumer 结构体

```c
// display_module/types.h (AUTO-GENERATED)
typedef struct {
    uint8_t head_power[4];        /* → state_module */
    uint8_t work_mode;            /* → state_module */
    /* PADDING: timer_remaining (2 bytes) */
    uint8_t __pad_0[2];
    /* PADDING: timer_active (1 byte) */
    uint8_t __pad_1[1];
} Display_StateInput_t;
```

- 只包含 `fields` 中声明的字段
- **其余字段自动填 padding**，保证 `offsetof()` 与 owner 一致
- 结构体名 = `consumers.{m}.struct_name` 或 `{Module}_{StructKey}_IN_t`

### 废弃字段

- Owner struct 仍保留，注释 `/* @deprecated: use {replaced_by} */`
- 若 consumer 引用了 deprecated 字段 → 生成器**报错**

## 五、工具

### generate_structs.py

```bash
python tools/generate_structs.py             # 生成所有 types.h
python tools/generate_structs.py --check     # 生成到 /tmp, diff 实际文件
python tools/generate_structs.py --struct X  # 只生成指定结构体
```

### check_structs.py

```bash
python tools/check_structs.py    # 验证一致性, 用于 pre-commit hook
```

内部逻辑: 调用 `generate_structs.py --check` → 如果实际文件与生成输出不一致 → 非零退出码 → 阻断提交。

额外检查:
- `structs.json` JSON 格式有效
- `serial` 单调递增
- consumer 未引用 deprecated 字段
- 类型在白名单内

## 六、操作流程

### 新增结构体
1. 编辑 `cfg/structs.json` → `structs` 下新增一个 key
2. 填写 `owner`, `suffix`, `fields`
3. 如有 consumer，填写 `consumers`
4. `serial += 1`
5. 运行 `python tools/generate_structs.py`
6. 运行 `python tools/check_structs.py`

### 新增字段
1. 编辑 `cfg/structs.json` → 在对应 struct 的 `fields` 数组追加
2. 如有新 consumer 需要此字段，在各 consumer 的 `fields` 列表追加
3. `serial += 1`
4. 运行 `python tools/generate_structs.py`

### 新增 consumer
1. 编辑 `cfg/structs.json` → 在对应 struct 的 `consumers` 下新增模块
2. 声明该模块需要的 `fields`
3. `serial += 1`
4. 运行 `python tools/generate_structs.py`
5. 更新 `interface_map.h`: 如有新的 __weak 通道，注册配对

### 废弃字段
1. 编辑 `cfg/structs.json` → 在 `deprecated` 下新增条目
2. 确认所有 consumer 的 `fields` 中已移除此字段
3. `serial += 1`
4. 运行 `python tools/generate_structs.py`

## 七、AUTO-GENERATED 协约

每个生成的 `types.h` 包含：

```c
/* ================================================================
   AUTO-GENERATED from cfg/structs.json  serial=3  schema=1.0
   DO NOT EDIT THIS FILE.
   
   修改跨模块结构体请编辑: cfg/structs.json
   然后运行:              python tools/generate_structs.py
   ================================================================ */
```

**协约条款**:

1. **禁止手动编辑 AUTO-GENERATED 区块** → `check_structs.py` 阻断
2. **所有结构体变更从 JSON 开始** → JSON 是唯一被编辑的数据源
3. **新 AI 上手路径**: 读到 AUTO-GENERATED → 知道不能改 → 找到 `structs.json` → 编辑 → 重新生成
4. **`serial` 防止回退**: JSON 的 serial < 生成文件的 serial → `check_structs.py` 报错
5. **建议提交生成文件**: 便于代码审查时查看结构体布局（也可 `.gitignore` 并从 JSON 恢复）

## 八、与 interface_map.h 的分工

| 文档 | 管什么 | 维护方式 | 验证工具 |
|------|--------|---------|---------|
| `structs.json` | 结构体字段 + 消费关系 | 人/AI 编辑 | `generate_structs.py --check` |
| 生成 `types.h` | 每模块的结构体声明 | 工具生成 | `check_structs.py` |
| `interface_map.h` | __weak 函数配对 + 签名 | AI 维护 | `check_weak_pairs.py` |

三者都不被 C 代码 `#include`。结构体变更改 JSON，通道变更改 `interface_map.h`。

## 九、不覆盖的场景 (V1.0)

- 嵌套结构体（struct 内字段类型是另一个 struct）
- 联合体 (union)
- 位域 (bit-field) — 嵌入式建议用 `uint8_t` + 掩码
- 函数指针字段 — 跨模块传递函数指针违反解耦原则
- 多级数组 — 只支持一维
