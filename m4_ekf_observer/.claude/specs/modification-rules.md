# 修改约束 — 在现有固件上安全修改

> 本项目不是从零构建，是在 M4 半桥固件基础上增量开发。
> 核心原则：**新代码可以错，旧代码不能破。**

---

## 一、不可修改区域 (No-Go Zone)

### 1.1 原厂固件库 (只读)

| 路径 | 内容 | 原因 |
|------|------|------|
| `src/RX32G410_FW_HAL_V1.3N/Drivers/` | CMSIS + HAL + DeviceSupport | 原厂分发，已验证 |
| `src/RX32G410_FW_HAL_V1.3N/` 下任何 `.s`/`.c` | 启动文件、系统文件 | 除非有寄存器级 bug 需要 workaround |

**例外**: 原厂固件库的 `.h` 可以读（include），绝对不要修改内容。

### 1.2 已验证稳定的模块

以下模块已经过硬件验证，修改需用户明确许可：

| 模块 | 涉及的寄存器/外设 | 风险 |
|------|-------------------|------|
| HRTIM 半桥驱动 | PER/CMP/DT 寄存器 | 功率级损坏 |
| ADC 采样 | 电压/电流/相位 ADC | 测量噪声影响 PID/EKF |
| MODBUS 帧解析 | UART2 DMA | 通讯断连 |
| IGBT 保护 | 硬件比较器 | IGBT 炸管 |

**这些模块的修改必须有用户明确指令，AI 不得自行决定改。**

## 二、安全修改区域

### 2.1 应用层 (app/) — 自由修改

| 路径 | 内容 | 自由度 |
|------|------|--------|
| `app/ekf/` | EKF 观测器 | 自由修改 (未在硬件运行过) |
| `app/pot_detect/` | 锅具检测 | 自由修改 |
| `app/var_gain_pid/` | 变增益 PID | 自由修改 |
| `app/data_logger/` | 数据记录 | 自由修改 |

### 2.2 工具层 (tools/) — 自由修改

PC 端 Python 工具，不影响固件。

### 2.3 MODBUS 寄存器扩展 — 需审批

- 新增只读寄存器 (如 0x1015+): 低风险，可自主添加
- 新增可写寄存器: 需确认不与其他从站冲突
- 修改现有寄存器含义: 禁止，会破坏 PC 工具兼容性

## 三、修改工作流

### 3.1 每次修改前

1. 确认修改的文件在哪个区域 (No-Go / 安全 / 需审批)
2. 如果需要改 No-Go 区域 → 停止，列出理由等用户确认
3. 读一遍要改的文件，理解现有逻辑

### 3.2 每次修改后

```
# 1. 编译验证
armcc -c --cpu Cortex-M4 --c99 -I... <modified.c> → 0e0w

# 2. MODBUS 工具验证 (如果改了寄存器相关)
python tools/ekf_tuner/m4_modbus_tool.py COM3 --read

# 3. 如果改了 EKF/PID，运行单元测试
python tools/ekf_tuner/run_ekf_tests.py
```

### 3.3 最小化原则

- 只改必要的行，不顺手重构无关代码
- 不"统一格式"、"优化命名" —— 保持与原固件风格一致
- 新增文件用项目现有风格 (中文注释, 显式循环展开)

## 四、与 four_head 项目的关系

| 维度 | four_head | m4_ekf_observer |
|------|-----------|-----------------|
| 开发模式 | 零依赖架构构建 | 现有固件上增量 |
| 约束系统 | L0-L2 铁律阻断 | 修改边界阻断 |
| 通信机制 | __weak 回调直调 | 现有 MODBUS 框架 |
| 强制检查 | check_deps.py / check_weak_pairs.py | 编译 + MODBUS 工具验证 |
| 方法论 | 产出方法论 | 消费方法论 (用到再取) |

**本项目的 AI 不强制执行 four_head 的六大铁律**。那些是 four_head 的约束系统，不适用于对现有固件的增量开发。

## 五、常见修改场景

### 新增 EKF 观测器
1. 在 20ms 控制周期中插入 `EKF_Update()` 调用点
2. 不改 PID 结构，在 PID 输出后再做 EKF 修正
3. 新增寄存器上报 EKF 中间变量 (R, L, φ_est)
4. PC 端先验证，再下放到 M4

### 修改功率控制
1. 读 `app/var_gain_pid/` 现有代码
2. 在原 PID 函数签名不变的情况下修改内部逻辑
3. 保持与 HRTIM 驱动的接口不变

### 修改 MODBUS 映射
1. 读 `src/` 中的寄存器处理逻辑 (MODBUS 从站框架)
2. 新增寄存器在 `0x1015+` 区域
3. 同步更新 `m4_modbus_tool.py` 的寄存器表
4. 更新 CLAUDE.md 的 MODBUS 寄存器表
