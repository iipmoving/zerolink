## 核心BUG：`load_data.m` 第94行 PERIOD计算错误

### 问题代码（第73-98行）

```matlab
dCNT = diff(CNT);
dCNT(dCNT <= 0) = [];      % ← 清除翻转点（正确）
...
CNT_range = CNT_max - CNT_min;  % ← 第94行：BUG在这里！
HRTIM_period_s = CNT_range * t_per_cnt_us * 1e-6;
f_sw = 1 / HRTIM_period_s;
```

### BUG分析

**CSV数据事实：**
```
CNT序列：25304 → 25768 → 120（绕回！）→ 504 → ...
CNT_max = 25768
CNT_min = 120
CNT_range = 25768 - 120 = 25648   ← 错误！
```

**正确PERIOD应该是26032：**
```
因为：每个采样CNT增384
      CNT绕回发生在 26032 → 绕回后 = 120（即26032 - 25912 = 120）
      所以 PERIOD = 26032
      
25648 vs 26032 → 差了 384 counts = 0.5μs
```

**影响链：**

| 参量 | 错误值（BUG导致） | 正确值 | 误差 |
|------|-----------------|--------|------|
| PERIOD (counts) | 25648 | 26032 | -384 (-1.5%) |
| f_sw | **29.85 kHz** | 29.50 kHz | +350 Hz (+1.2%) |
| T_hrtim_us | 33.40 μs | 33.90 μs | -0.5 μs |
| DT2 | **1.948 μs** | 2.344 μs | **-0.4 μs（严重）** |
| D_U | 36.4% | 36.1% | 接近 |

### 修复方案

在`load_data.m`第58-98行之间加入PERIOD检测逻辑：

```matlab
%% 4) 自动检测 HRTIM 时钟 & 周期（修复版）
% 方法：找CNT绕回点，计算真实PERIOD
dCNT = diff(CNT);

% 找绕回点（负跳变）
wrap_idx = find(dCNT < 0);
if ~isempty(wrap_idx)
    % 有绕回：PERIOD = CNT_before_wrap - CNT_after_wrap + 2^16(?)
    % 简化：直接用CNT增量推算
    % CNT每步增384（0.5μs × 768MHz / 1000?）
    % 更稳健：找CNT最大值点，下一个值就是绕回后的值
    [CNT_max_val, CNT_max_idx] = max(CNT);
    CNT_after_wrap = CNT(CNT_max_idx + 1);  % 绕回后第一个值
    PERIOD_counts = CNT_max_val + (2^16 - CNT_max_val) + CNT_after_wrap;
    % 简化版（假设16位）：PERIOD = CNT_max + (2^16 - CNT_max) + CNT_min_after_wrap
    % 但更通用的做法：直接找CNT的模
    PERIOD_counts = round(median(diff([CNT(:); CNT(1)+2^16]))); % 估计
else
    PERIOD_counts = CNT_max - CNT_min;
end
```

**更简单的修复（推荐）：**

由于CSV中已知CMP_LOFF=25000且CMP_UON=768，直接用四边沿算PERIOD：
```matlab
% 从CMP边沿推算PERIOD（最准）
% PERIOD = CMP_LOFF + (wrap_adjust) - CMP_UON + ...
% 简化：假设无绕回的CMP_UON到下一个CMP_UON = PERIOD
PERIOD_counts = CNT_range;  % 暂存

% 修正：如果CNT有绕回，用绕回边界修正
wrap_at = find(diff(CNT) < 0, 1);
if ~isempty(wrap_at)
    % CNT在wrap_at处从~26000跳到~0
    % 所以PERIOD ≈ CNT(wrap_at) + (2^16 - CNT(wrap_at))
    % 但更准的是：看CMP_FIXED，用已知的768MHz时钟反推
    hrtim_clk_hz = 768e6;  % 从t_per_cnt推算
    PERIOD_counts = round(hrtim_clk_hz / 29.85e3);  % 用输出反推
end
```

**实际最好的修复：直接用CMP推算**

```matlab
% 因为CMP_UON/CMP_UOFF/CMP_LON/CMP_LOFF是固定的，
% 它们相对于PERIOD设置，所以：
% PERIOD = max(CMP_LOFF, CMP_UOFF) + deadtime_zone...
% 最简单：PERIOD = CNT_increment_per_period + ...
% 从CSV知：t=35.0μs时CNT=120（刚绕回），t=34.5μs时CNT=25768
% 所以PERIOD = (25768 - 120) + 384 = 26032 ✓
```

## 逐文件审查结果

### ✅ `calibration.m` — 正确

- ADC标定值验证：
  - ADC=2850 → V=2850×0.10606 ≈ 302V ✓（整流后母线）
  - ADC=795 → I=795×0.02523 ≈ 20.06A ✓
- CT变比2000:1，取样2kΩ，分压10k:330 → 公式正确

### ✅ `load_data.m` — 大部分正确，PERIOD计算有BUG

| 功能 | 状态 | 说明 |

| 数据模式检测 | ✅ | 20ms→模式A正确 |

### ⚠️ `calc_timing.m` — 受PERIOD BUG影响

- DT1计算（上关→下开）：✅ **正确** = CMP_LON - CMP_UOFF = 768 = 1.0μs
- DT2计算（下关→上开）：❌ **受PERIOD错误影响** → 输出1.948μs（应为2.344μs）
- 控制模式判别：⚠️ **逻辑有误**
  - 代码第102行：`if D_std < 2 && mean(D_U_pct) > 45 → FM模式`
  - 但CSV是固定占空比36.4%，`mean(D_U_pct)=36.4 < 45` → 误判为PWM模式
  - 实际应判别为"固定频率固定占空比"，不属于FM或PWM

### ✅ `calc_waveform.m` — 正确

- 谷值检测法（针对整流后电流）：✅ 正确
- f_res计算：从谷值间隔算半周期 → f_res = 1/(2×T_half) → ✅ 正确
- CSV中谷值约每17μs一个 → f_res ≈ 1/(2×17μs) ≈ 29.4kHz（接近f_sw，合理）

### ⚠️ `calc_phase.m` — 方法正确，但依赖PERIOD

- 相位提取原理：
  - `φ = (t_valley - t_UON) / T_sw × 360°` → ✅ 正确
  - 但`t_per_cnt_us`受PERIOD BUG影响 → φ可能有误差
- 输出φ=+59.7°（感性）→ 需核实是否合理

**手动验证φ：**
- 电流谷值（I最小）在t≈24μs
- CMP_UON在t=0（ CNT=768对应的时间）
- 时间差 = 24μs
- φ = 24μs / 33.9μs × 360° = 255° → 归一化到[-180,180] = -105°或+255°
- 但代码只保留`abs(phi_deg) <= 90` → **+59.7°可能是另一段数据**

→ 需要更多谷值点验证

### ⚠️ `calc_power.m` — 公式正确，数值受前面影响

- 基波法：`P = V_fund_RMS × I_RMS × cos(φ)` → ✅ 公式正确
- V_fund_RMS = Vdc × √2/π × sin(π×D) → ✅ 正确
- 但`V_fund_RMS`系数可能有误：
  - 50%占空比：V_fund_RMS = Vdc × √2/π ≈ Vdc × 0.450
  - 非50%：× sin(π×D)
  - D=36.4%，sin(π×0.364)=sin(65.5°)=0.910 → ✅ 正确

### ⚠️ `calc_rlc.m` — 物理思路正确，但输入受BUG影响

- L计算（KVL）：`L = (Vdc/2 + V_C_peak) / (I_peak × ω)` → ✅ 物理正确
- 但`V_C_peak = I_peak / (ωC)` → ⚠️ 这个是电容电压幅值？
  - 实际：V_C_peak = I_peak/(ωC) 是电容电压的频域幅值 → ✅ 正确
- Q值：`Q = tan(φ) / (f_sw/f_res - f_res/f_sw)` → ✅ 正确（串联RLC）

**手动验证L：**
```
Vdc = 302V, Vdc/2 = 151V
I_peak = 20.04A
ω = 2π×29500 = 185354 rad/s
V_C_peak = 20.04 / (185354 × 0.9e-6) = 120.1V
L = (151 + 120.1) / (20.04 × 185354) = 271.1 / 3710000 = 73.0μH
```
输出L=71.78μH → 接近（误差来自f_sw取值）
